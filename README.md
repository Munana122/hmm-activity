# Human Activity Recognition with a Hidden Markov Model

Formative 2 – Hidden Markov Models. Smartphone accelerometer and gyroscope data are used to infer four hidden activity states (**standing, walking, jumping, still**) with a Hidden Markov Model implemented from scratch in numpy (Viterbi decoding and Baum-Welch training).

## Repository contents

├── data/                            # training recordings (.csv)

├── raw/                             # (optional) raw Sensor Logger exports, one folder per recording

## Dataset

- **Device and app:** one smartphone, Sensor Logger. Accelerometer (x, y, z) and gyroscope (x, y, z) recorded together.
- **Native sampling rate:** about 100.6 Hz. All recordings are resampled to a common 50 Hz in the notebook.
- **Activities:**

| Label | Description |
| --- | --- |
| `standing` | phone held steady at waist level |
| `walking` | consistent pace |
| `jumping` | continuous jumps |
| `still` | phone on a flat surface, no movement |

- **File naming:** `<activity>_<person>_<NN>.csv`, for example `walking_p1_03.csv`. Files in `data/test/` follow the same pattern and are never used for training.
- **File format:** columns `timestamp` (seconds), `ax, ay, az` (accelerometer), `gx, gy, gz` (gyroscope). Each recording lasts about 5-10 s.
- **Size:** 64 recordings: 52 for training (13 per activity, recorded 28-29 October 2026) and 12 for testing (3 per activity, a separate session on 1 November 2026). Training time per activity: standing 137 s, walking 128 s, jumping 117 s, still 141 s.

## Method summary

1. **Pre-processing:** low-pass filter (if native rate > 50 Hz), linear interpolation to 50 Hz, trim 0.5 s at both ends.
2. **Windowing:** 2 s windows (100 samples) with 50% overlap.
3. **Features (15 per window):** RMS, SMA and peak-to-peak (time); dominant frequency, spectral energy and spectral entropy from the FFT; correlation between accelerometer axes. Variance-like features are log-transformed, then all features are Z-score normalized using training statistics.
4. **HMM:** 4 hidden states, diagonal-Gaussian emissions, learned transition matrix A and initial distribution π. Viterbi for decoding. Baum-Welch for training, stopping when the average log-likelihood per window improves by less than 1e-4.
5. **Evaluation:** per-activity sensitivity, specificity and accuracy, confusion matrix, transition and emission heatmaps, and a decoded-sequence plot, all on unseen test recordings.

## How to run (Google Colab)

1. Open [Google Colab](https://colab.research.google.com) and choose File, then Upload notebook, and select `HMM_Activity_Recognition.ipynb`.
2. Run the cells from top to bottom.
3. In section 2, set `DATA_SOURCE` to one of:
   - `"sensorlogger"`: upload your raw Sensor Logger `.zip` exports. The latest `N_TEST` recordings per activity become the test set.
   - `"upload"`: upload a `data.zip` containing the `data/` folder (with `data/test/`).
   - `"github"`: set `GITHUB_URL` to this repository so the notebook clones it and reads `data/`.
   - `"drive"` or `"local"` for Google Drive or files already in the Colab session.
4. The notebook saves plots to `figures/` and writes `results_table.csv` and `dataset_inventory.csv`.

Requirements (all pre-installed in Colab): numpy, pandas, scipy, matplotlib.

## Results
